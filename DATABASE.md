# VENDO — база данных

Схема: `src/server/db/schema.ts`. Миграции (SQL): `drizzle/`. Применяются автоматически для локального PGlite и командой `npm run db:migrate` для внешнего PostgreSQL.

## Таблицы

| Таблица | Назначение |
|---|---|
| `regions`, `cities` | Регионы и города (названия `jsonb {ru,uz,en}`) |
| `users` | Аккаунты: email и/или логин, хеш пароля (scrypt), роль, статус, язык, город, контакты, `show_phone` |
| `sessions` | Сессии: id = SHA-256 токена из cookie, срок действия |
| `password_reset_tokens` | Токены восстановления (хеш, 1 час, одноразовые) |
| `categories` | Дерево категорий (`parent_id`), slug, иконка, порядок, активность, разрешённые типы, SEO |
| `category_attributes` | Характеристики категории: ключ, тип, обязательность, фильтр, ограничения |
| `category_attribute_options` | Варианты для select/multiselect |
| `listings` | Объявления: тип, цена/диапазон/период/залог, валюта, состояние, город, контакты, статус, причина отклонения, `ranked_at`, `highlight_until`, `featured_until`, `search_vector` (generated) |
| `listing_attribute_values` | Значения характеристик (типизированные колонки: option/text/number/bool/date) |
| `listing_images` | Фото (ключи хранилища, размеры, порядок; первое = главное) |
| `listing_status_history` | История смен статуса (кто, когда, причина) |
| `favorites` | Избранное (PK user+listing) |
| `listing_daily_stats` | Дневные агрегаты: просмотры, показы телефона, звонки, Telegram, избранное (без персональных данных) |
| `search_queries` | Счётчики реальных поисковых запросов (для подсказок/популярного) |
| `stores` | Магазины (1 на пользователя), `verified_at` ставится только сотрудником |
| `subscription_plans`, `store_subscriptions` | Тарифы магазинов и подписки |
| `promotion_plans`, `promotions` | Тарифы продвижения и заявки/активные продвижения |
| `payments` | Задел для платёжного провайдера |
| `ad_placements`, `ad_campaigns` | Рекламные места и кампании (расписание, таргет по категории, показы/клики) |
| `reports` | Жалобы на объявления и пользователей |
| `notifications` | Уведомления (тип + параметры, текст рендерится на языке читателя) |
| `admin_audit_logs` | Журнал административных действий |
| `content_pages`, `home_collections` | Страницы/FAQ и подборки главной |
| `app_settings` | Настройки платформы (ключ → jsonb) |
| `rate_limits` | Счётчики ограничения частоты |

JSON используется только для переводимых строк, флагов функций тарифа, фильтров подборок и метаданных аудита. Основные сущности и всё, по чему идёт фильтрация, — реляционные колонки.

## Индексы

Статус+`ranked_at`, категория+статус, город+статус, пользователь+статус, цена, GIN по `search_vector`, GIN-trigram по `title`, индексы по значениям характеристик (`attribute_id, option_id` и `attribute_id, value_number`), уникальные `lower(email)` / `lower(username)`.

## Удаление

- Объявления — мягкое удаление (`deleted_at`).
- Категория удаляется только без подкатегорий; объявления переносятся в выбранную категорию в одной транзакции.
- Пользователи не удаляются из интерфейса (блокировка); каскады настроены на уровне внешних ключей.

## Безопасный процесс изменений

1. Изменить `schema.ts`.
2. `npm run db:generate` → проверить SQL в `drizzle/`.
3. Прогнать `npm test` (тесты применяют все миграции к чистой БД).
4. В продакшене: резервная копия → `npm run db:migrate`.

## Резервное копирование

- Supabase Free: автоматических бэкапов с восстановлением на момент времени нет — делайте `pg_dump "$DATABASE_URL" > backup.sql` по расписанию (например, GitHub Actions раз в сутки) и храните вне Supabase.
- Восстановление: `psql "$DATABASE_URL" < backup.sql` на пустую БД.
- Локально: остановить сервер и скопировать папку `.data/`.
